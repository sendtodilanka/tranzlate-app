Tranzlate — UI Design Brief (for Claude Design)

Android translator app · Material 3 · behaviour north-star = the Google Translate Android app. Use THIS design system's palette (P1 Google Blue — see the Foundations cards) for every screen, light AND dark.

Design these screens (phone-first, 1080×2400-ish frame; each in light + dark)

Direction (owner-locked 2026-07-22): the INTERACTION skeleton follows the 2026 evolved-GT session model (turn-based, live-as-you-type, thumb-zone chips) — but the VISUAL identity must be distinctly Tranzlate's own. If a screen could be mistaken for Google Translate, it has FAILED the brief. Owner's #1 product goal: every translator on Play looks the same — this one must not.

Uniqueness mandate (added 2026-07-22 after first review round)

  • Keep the skeleton, change the skin: distinctive accent identity (NOT Google-blue-on-white), signature result-card treatment (shape/border/fill that becomes "ours"), a custom mode-selector element, a recognizable home-hub composition.
  • Palette: SETTLED in Round-5 — the P1 Google-Blue scheme is the app palette (see the Colour bullet in the Round-5 section). Uniqueness comes from composition, ambient gradient, texture and typography — not from picking an unusual hue. WCAG AA (≥4.5:1 text) is non-negotiable.
  • Typography personality allowed for RESULT text (display-weight or a distinctive face) — body/labels stay system-clean.
  • Signature motion/detail notes welcome (e.g., result-card reveal, gradient underline while translating).
  • AI-app energy is on-brand (owner's heritage design was chat-styled) — expressive, modern, but never at the cost of the speed rules below.
  • 0. Home hub (NO bottom nav bar — hub model): top bar = Saved/bookmark icon (left) · "Tranzlate" wordmark centered · avatar/menu (right, opens Settings/account); huge "Enter text" placeholder + handwriting/mic affordance on a big quiet canvas (tapping opens a translate session); bottom thumb-zone = language chips [English] ⇄ [French] above an action row: "Conversation" · center primary MIC (large filled circle) · "Camera" — labeled round buttons. Our delta: small mode chip ("Automatic ▾") near the top.
  • 1. Translate session (THE core screen): "< Home" pill top-left + History ⏱/bookmark/⋯ (right; while typing: edit + ✕ + ⋯). BOTH sides rich: "English" label → large input text ("hello") → phonetic ("həˈlō") → speaker + copy; divider; "French" label → blue result ("bonjour") → transliteration → speaker · copy · 👍👎 feedback · ⋯. Below the result: an "Examples of hello" dictionary card (quote rows). "+ New translation" pill bottom-right starts the next entry (turn model). Language chips at BOTTOM above keyboard; while typing show a history quick-recall row ("recent: Hello, man. → හෙලෝ මචන්.") above the chips. NO send button on free engines (live as-you-type); Advanced-AI variant: explicit send action + "15/20 today" counter chip near the mode chip.
  • 2. Model picker (bottom sheet): 4 options — Automatic (selected) / Offline on this device / Standard online / Advanced AI (lock + "Premium" chip + "15/20 today" counter).
  • 3. Language picker: search, "Detect language", Recent, All (A→Z) with small "Downloaded ⬇ / Online-only ☁" badges. No download buttons here.
  • 4. History & Saved: list with source + translation + EN→FR, star to save; separate Saved filter; friendly empty state.
  • 5. Settings + Offline languages: settings list; offline-languages manager rows: Downloaded (delete) / Downloading (spinner + Stop, NO percent) / Not downloaded (⬇) / Failed (Retry) / "Wi-Fi only" toggle.
  • 6. Paywall: benefits, two plan cards (Plus $4.99/mo "Recommended", Premium $9.99/mo), Subscribe CTA with full price/renewal disclosure UNDER it, Restore/Terms/Privacy links, loading + error states.
  • 7. Camera translate: viewfinder with live translated overlays, capture, permission-needed state.
  • 8. Error / limit states: inline error + Retry (never a popup dead-end); daily-limit bottom sheet (dismissible, "Upgrade" + "Not now").

Deliverable format (MANDATORY — added after round 2)

Every design request = one COMPLETE SET in ONE identity: 4 frames together — Home hub (light) · Home hub (dark) · Translate session (light) · Translate session (dark). Never a single screen alone; never mixed identities within a set. Additional screens later join the same identity.

⚠ Surface & sizing rules (owner round-7 — the two things that felt wrong)

  • 1. Elements must SIT IN the background, not on top of it (GT/Gemini do this well):
    • The page background is the soft tinted wash; anything floating on it (composer, tiles, chips, drawer sheet) is a lighter surface — in light mode pure/near white (surfaceContainerLowest), in dark mode an elevated grey (surfaceContainer/High). Separation comes from the lightness step, not from outlines.
    • Do NOT draw hairline-outlined boxes whose fill is the same value as the page — that reads as "stuck on". Outlines only where there is no lightness step available.
    • Secondary/utility controls use soft tonal fills tinted from the background hue (like GT's pale-blue circles), never saturated blocks.
    • Exactly ONE saturated accent element per screen — the primary action (Translate / mic). Everything else is neutral or tonal.
    • Shadows: barely-there, ambient. Flat + lightness step first.
  • 2. Compact sizing, full-width rhythm (from the owner's own earlier app):
    • Quick-action tiles are compact (≈64–72dp tall, icon + short label, no big padding blocks) so the canvas keeps free space for future items — the grid must still look intentional with only 2 tiles.
    • Inside the composer, the control row is compact in height but spans the FULL width: the language chips stretch to fill the available width with the swap control between them, and the primary action sits at the end — no cramped, floating little pills in the middle of an empty row.
    • Keep vertical rhythm at 8dp; prefer more breathing space in the canvas over bulky components.

Professional polish rules (MANDATORY)

  • Gradient discipline: a gradient may appear on AT MOST 1–2 signature elements per screen (e.g., the mode orb OR the translating-progress underline OR one hero accent). NEVER on divider lines, hairlines, borders of ordinary components, icons, or any body text. Dividers = subtle neutral hairlines only.
  • Restraint: one accent family + calm neutrals per identity. No rainbow, no glows on multiple elements, no decorative noise.
  • System discipline: one consistent corner-radius scale, 8dp spacing rhythm, one type scale; every state (pressed/disabled) designed, not improvised. Elevation subtle — flat-first.
  • Quality bar: should look like a top-tier product-design portfolio shot (think Linear/Arc/Things-level polish), not a template.

⭐ ROUND-5 LOCKED DIRECTION (owner, 2026-07-22) — supersedes everything below

Reference apps the owner loves (taste anchors): Gemini app — ambient soft-gradient background (light: white→pale wash at the bottom; dark: near-black→deep tinted glow), sparkle mark, dotted-ring icon treatment, hamburger-left + model-chip-center top bar, floating pill composer. Claude app — the side navigation drawer (wordmark, icon list of sections, "Starred"/"Recents", floating "+ New" pill, account row pinned at the bottom) and its greeting composition ("Afternoon, Dilanka") — note: the SERIF face itself is rejected (see Typography). Build the Tranzlate identity from THIS energy — not from Google Translate, and NOT the electric-violet round.
  • Colour (owner-FINAL, round 6): the app palette is P8 "Tranzlate Teal (cool-mono)" — see the "Color roles" card. Teal is the accent and it stays (the owner liked it); what was removed is every WARM colour — no coral, no gold, no violet, no rainbow. Support tones are cool blues, surfaces/neutrals/error come from the Google-blue P1 set (near-white light, tonal-grey dark). Ambient gradient = teal→blue wash. All 13 contrast pairs verified AA/AAA.
  • Drawer motion (owner-requested): adopt the Claude-app drawer transition — the drawer slides in from the left while the main content is pushed right, scaled down slightly with rounded corners and dimmed, moving as one continuous gesture-driven motion (Compose: predictive-back / draggable drawer with scale+corner animation).
  • Typography (owner-FINAL, round 6): NO serif and NO display/branded face. Use a clean, neutral system-class sans — Roboto / Open Sans / Inter class — at every level, including the greeting and the translated result; differentiate by SIZE and WEIGHT, not by an exotic face. Why: the result text can be Sinhala, Arabic, CJK — a neutral sans pairs cleanly with the Noto family so every script renders consistently. Personality comes from composition, the ambient gradient and the teal accent — not from the typeface.
  • Composer behaviour spec (owner-verified against the Gemini captures — implement EXACTLY):
    (a) Idle, no keyboard: composer = single-line PILL pinned at the bottom; canvas above shows greeting + quick actions.
    (b) Keyboard open, field EMPTY: pill sits directly above the keyboard; the greeting stays visible and RE-CENTRES ITSELF in the space left between the top bar and the composer — the canvas is a flexible region that always vertically centres its content, so nothing is pushed up or clipped when the keyboard appears.
    (c) Keyboard open, text entered, fits one line: still a PILL and the text sits INLINE on the same row as the controls; the trailing button swaps from mic to the primary Translate action; the greeting/canvas content is HIDDEN as soon as the first character is typed (not only when it wraps).
    (d) Text wraps to multiple lines: the pill MORPHS into a rounded CARD — the text moves to its own area on TOP and the controls (language chips + swap + Translate) reflow onto a row BENEATH it; the card grows with content to a max height, then scrolls internally.
    (e) Collapse hysteresis (critical): once expanded to the card layout it does NOT return to the inline pill when text is deleted back to one line/one character — it collapses back to the pill only when the field is completely empty (prevents the layout jumping while editing).
    This pill ⇄ card morph is a signature interaction — design states (a)–(d) and note (e). Layout rule for every keyboard-open state: the composer DOES sit directly above the keyboard (Gemini-style, correct); everything else treats the band between the top bar and the composer as its viewport and lays out responsively — vertically centred, never clipped or pushed off-screen.
  • Home skeleton (final): top bar = ☰ hamburger (opens the drawer) · centered mode chip ("✦ Automatic ▾") · right = new/clear action. Canvas = serif greeting + quick-action tiles (Conversation, Camera today; grid must scale to 5-6 future tiles). Bottom = the input cluster: multi-line text field + [English] ⇄ [සිංහල] chips + Translate button.
  • Side drawer (Claude-style, required): wordmark + sections (Search · History · Saved · Offline languages · Settings) · "Recents" list of past translations · account row pinned bottom (avatar, tier chip Free/Premium). NO "+ New translation" pill (owner 2026-07-22 — the composer itself starts a new translation).
  • ⚠ BEHAVIOUR CHANGE (owner decision, supersedes C-2/live-translate): auto-translate-as-you-type is REMOVED. Every engine — including the free ones — uses an explicit Translate button. Result opens on a SEPARATE result screen (GT-style). The result screen does NOT carry the composer/input cluster (owner 2026-07-22) — it is a focused reading surface; return via back. A shared-element/transition still ties the two screens together visually.
  • Empty-state care: a first-run user has no Recents — the canvas (greeting + tiles) must feel complete and intentional with zero history; Recents appear in the drawer and (optionally) below the tiles once they exist.
  • Keyboard frame still mandatory, and the text area must be generously large for long text.

Round-4 comparison decisions (owner, 2026-07-22) — superseded by Round-5 above where they conflict

  • Skeleton is now OPEN: the GT session skeleton is no longer locked. The layout DNA to explore = Tranzlate Heritage: a BOTTOM input cluster card (text field + language chips + ⇄ swap + contextual 🎤/➜ button embedded), canvas above for content. Behaviour rules below still apply.
  • Two competing designs, SAME identity (Midnight electric-violet) so only layout differs:
    Design A "Heritage greeting": canvas = toned-down personality greeting (professional, no rainbow) + feature tiles; results = STACKED FEED rising above the bottom input (chat-history feel).
    Design B "Heritage minimal": canvas = quiet "Enter text"-style emptiness or a BETTER alternative to tiles if one exists; results = REPLACE-IN-PLACE single card.
  • Feature tiles must be future-proof: 2 items today (Conversation, Camera) but the layout must scale to 4–6 (wrapping grid or scrollable row) without redesign.
  • Latency-aware result states are part of the design: every result presentation shows 3 states — instant (offline engine), "translating…" shimmer/progress (slow online), network error + inline Retry.
  • Keyboard-open frame is MANDATORY in every set: layout adjusts to the IME; the input area is LARGE and grows (multi-line) so long text is comfortably editable.
  • Screens may be logically separate but must FEEL continuous — keep element positions consistent across states so shared-element transitions (Compose) can bind them.

Hard rules (from the product spec — do not break)

Free engines translate LIVE while typing — no Translate button. Only the metered "Advanced AI" mode shows an explicit Translate action + usage counter.
Every error/empty/blocked state offers a next step (Retry / alternative / guidance) — no dead ends. Never an ad or paywall on Back-press.
Neutrals/surfaces may start from the P1 baseline, but the ACCENT/identity layer should be distinctly non-Google (see Uniqueness mandate). Touch targets ≥48dp. Text ≥4.5:1 contrast (both themes). Material 3 component behaviours (chips, tonal buttons, sheets with drag handle) — styled with our identity.

Feel

  • AI-app conversational: each translation reads like a turn — input up top, response card below with feedback thumbs; "+ New translation" like a next message. Session-based like 2026 Google Translate, but with our own personality.
  • Quiet, near-white, content-first; blue for actions/accents only. Pill-shaped controls, soft cards.
  • The input is the hero — no marketing headline on the hub, no fake chat greeting text.
  • Friendly for a non-technical audience; benefit-named modes, visible limits, honest progress.
  • Future-ready: response cards may later grow AI follow-up chips ("Formal", "Explain", "Nuance") under a result — leave visual room for that row.
