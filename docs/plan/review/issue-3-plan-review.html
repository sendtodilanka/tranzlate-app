මොකක්ද මේ "අත්තිවාරම" (scaffold) කියන්නේ?

ගෙයක් හදනකොට මුලින්ම කරන්නේ කාමර හදන එක නෙවෙයි — අත්තිවාරම දාලා, කණු ගහලා, වහලේ රාමුව හදන එක. ඒක හරියට හැදුවොත් ඊට පස්සේ කාමර එකින් එක ලේසියෙන්, ආරක්ෂිතව හැදෙනවා. වැරදියට හැදුවොත් — පරණ app එකේ වුණේ ඒකයි — පස්සේ හැම දෙයක්ම එකිනෙකට පැටලිලා, එක තැනක් fix කරන්න තැන් අටක් හොයන්න වෙනවා.

මේ පියවරේදී අපි හදන්නේ:

  • කැට 26ක රාමුව — app එකේ හැම වැඩකටම වෙන වෙනම "පෙට්ටි", එකිනෙකට සම්බන්ධ වෙන නීති එක්කම (කොටස 2).
  • පාට / අකුරු / ඉඩ පද්ධතිය — මුළු app එකම එක පෙනුමකින් තියන්න (කොටස 5).
  • තිර අතර යන රාමුව — දුරකථනේ, ටැබ්ලට් එකේ, ලොකු තිරයක — තුනේම හරියට පේන විදිහට (කොටස 6).
  • "අච්චුව" — එක codebase එකෙන් apps කිහිපයක් හදන්න පුළුවන් සැකැස්ම (කොටස 4).
  • "බොරු එන්ජිම" — පරීක්ෂණ 100%ක් විශ්වාස කරන්න පුළුවන් වෙන්න (කොටස 3).
මේ පියවරේ නැති දේ: ඇත්ත පරිවර්තනය තාම නෑ. Text තිරය, කැමරාව — ඒවා ඊළඟ පියවර වල. මේ පියවර ඉවර වුණාම ඔබට බලන්න ලැබෙන්නේ: app එකක් open වෙනවා, අලුත් පාට තේමාව පේනවා, පහළ tab bar එකෙන් තිර මාරු වෙනවා, "බොරු එන්ජිමෙන්" පරීක්ෂණ දුවනවා. කාමර නැති, ඒත් හැම කාමරයකටම තැන හදපු ගෙයක් වගේ.

ඔබ කලින් අනුමත කරපු "මොළ 4 + තිර නිකම් අහනවා" ව්‍යුහයම තමයි මේ — දැන් ඒක ඇත්ත ගොඩනැගිලි කැට (modules) වලට කඩලා. හිතන්න නගරයක් වගේ:

තිර (කඩ) → මොළ (කර්මාන්තශාලා) → ගබඩා/සේවා. කඩේකට කර්මාන්තශාලාවේ ඇතුළට යන්න බෑ — ඉල්ලන්න විතරයි පුළුවන්. ඒ නීතිය කැඩෙන්නේ නැති විදිහට කැට බෙදලා.

පහළින් රවුම් 4 — එකක් open කරලා, ඕනම කැටයක් click කළාම ඒක මොකද කරන්නේ කියලා සරලව කියනවා. ඕනම කැටයක් ගැන අදහසක් තියෙනවා නම් ඒ කැටේ ඇතුළේම 💬 බොත්තමක් තියෙනවා.

ඇයි 26ක්? — වැඩිත් නෑ, අඩුත් නෑ. හැම කැටයක්ම "කුලිය ගෙවනවා" (ඒකට හේතුවක් තියෙනවා): වෙනම test කරන්න පුළුවන්, වෙන app එකකට දෙන්න පුළුවන්, නැත්නම් නීතියක් රකිනවා. සමහර කැට පස්සේ කුඩා වැඩියි කියලා පේනවා නම් ඒවා ඒකාබද්ධ කරන "trigger" ලකුණුත් සැලැස්මේ ලියලා තියෙනවා — හිතුවක්කාරව ලොකු කරන්නේ නෑ.

"බොරු එන්ජිම" — පරීක්ෂණ කවදාවත් බොරු නොකියන්න

ඇත්ත පරිවර්තන එන්ජින් (Google, MLKit…) හැමදාම එකම උත්තරේ දෙන්නේ නෑ — network එක, model version එක අනුව ටිකක් වෙනස් වෙනවා. ඒ නිසා ඒවා උඩ automated පරීක්ෂණ දැම්මොත් පරීක්ෂණ සමහර දවසට fail වෙනවා, සමහර දවසට pass — කාටවත් විශ්වාස කරන්න බෑ.

විසඳුම: නාට්‍යයක රඟපාන නළුවෙක් වගේ "බොරු එන්ජිමක්". ඌට කලින්ම කටපාඩම් කරපු පිළිතුරු ටිකක් දීලා තියෙනවා — "Good morning" ඉංග්‍රීසි→ප්‍රංශ ඇහුවොත් හැමදාම, හැම වෙලේම "Bonjour (fake)" කියනවා. ඒ නිසා පරීක්ෂණයක් fail වුණා නම් ඒ අපේ code එකේම වැරැද්දක් — කවදාවත් "network එක හින්දා" නෙවෙයි.

  • App එකේ copy දෙකක් හැදෙනවා: ඇත්ත එන්ජින් සහිත එක (ඔබ Play Store එකට දාන එක) + බොරු එන්ජිම සහිත test copy එක.
  • Test copy එකේ ඇත්ත Google/AdMob/Qonversion කෑලි ඇතුළෙම නෑ — අතින් වැරදිලාවත් ඇත්ත server එකකට කතා කරන්න බැරි විදිහට.
  • බොරු copy එක Play Store එකට යන එක තුන් ආකාරයකින් block කරලා (build එකේම, CI පරීක්ෂාවක්, publish-lock එකක්) — මාරු වෙන්න බෑ.
මේ ක්‍රමය Google ම තමන්ගේ ආදර්ශ app එකේ (Now in Android) පාවිච්චි කරන, ලේඛනගත ක්‍රමයමයි — අපේ specs වල TEST contract එකත් ඉල්ලන්නේ මේකමයි.
4

එක අච්චුවෙන් apps ගොඩක් — "Spanish Translator" පරීක්ෂාව

ඔබට ඕන වුණේ: එක codebase එකෙන් Offline Translator, Spanish Translator, French Translator… වගේ apps කිහිපයක් — අලුත් app එකක් හදනකොට code එකට අත තියන්නේ නැතුව. කේක් අච්චුවක් වගේ: අච්චුව එකයි, කේක් ගොඩයි — වෙනස් වෙන්නේ රසය (නම, icon එක, භාෂාව, ගිණුම්) විතරයි.

මේ සැලැස්ම ඒක ඇත්තටම කරනවද කියලා බලන්න, "Spanish Translator" කියලා දෙවෙනි app එකක් හදනවා කියලා simulation එකක් කළා (ස්වාධීන පරීක්ෂකයෙක් අතින්). ප්‍රතිඵලය — අලුත් app එකකට ඕන වෙන්නේ:

  • App icon එක + නම (config ගොනුවක)
  • Play Store ගිණුම් විස්තර + app හැඳුනුම (id) + අත්සන (signing)
  • ඒ app එකේම දැන්වීම් / දායකත්ව ගිණුම් අංක
  • Default භාෂා (උදා: Spanish) + on/off කරන features (උදා: කැමරාව off)
  • Code එකේ එක අකුරක්වත් වෙනස් කරන්න වෙන්නේ නෑ — පරීක්ෂකයා හැම ගොනුවක්ම trace කරලා තහවුරු කළා ✓
පරීක්ෂාවෙන් හොඳ අනතුරු ඇඟවීම් 2ක් ආවා (දෙකම සැලැස්මට ඇතුළත් කළා): (1) app ලැයිස්තුව code ගොනුවක නොතියා config ගොනුවක තියන්න — නැත්නම් අලුත් app එකක් දාද්දී "code වෙනසක්" වෙනවා; (2) කැමරාව වගේ feature එකක් off කරන switch එක පළමු දවසේම රාමුවට හදලා තියන්න ඕන.

පාට, අකුරු, ඉඩ — හැම තැනම එක තැනකින්

පරණ app එකේ පාට/අකුරු තැනින් තැන අතින් ලියලා තිබුණා — ඒකයි එක තිරයක් එක විදිහයි, තව තිරයක් තව විදිහයි වුණේ. අලුත් app එකේ නීතියක්: කිසිම තිරයක පාටක්, අකුරු ප්‍රමාණයක්, ඉඩක් අතින් ලියන්නේ නෑ — ඔක්කොම එන්නේ එක "පාට පෙට්ටියකින්" (design tokens). පාටක් වෙනස් කරන්න ඕන නම් එක තැනක් වෙනස් කළාම මුළු app එකම මාරු වෙනවා.

ඔබේ brand එකේ පාට — teal (නිල්-කොළ) + coral (තැඹිලි-රෝස) — designer ලේඛනයේ තියෙන, අකුරු කියවීමේ පහසුව (contrast) ගණනය කරලා තහවුරු කරපු අගයන්ම:

⚠ ඔබෙන් තහවුරුවක් ඕන (තීරණ කොටසේ 9.2): ලේඛන දෙකක පාට යෝජනා දෙකක් තිබුණා — එකක "නිල් + රෝස" seed එකක් (අවසන් නොකළ proposal එකක්), අනෙකේ මේ උඩ පෙන්නපු සම්පූර්ණ teal+coral පද්ධතිය (designer "buildable" කියලා confirm කරපු). අපි teal+coral සම්පූර්ණ පද්ධතිය ගන්නවා කියලයි යෝජනාව.

Google Translate වගේම: ප්‍රධාන වැඩ (Text · Camera · History · Settings) එක tap එකකින් ළඟා වෙන්න ඕන. තිරේ ප්‍රමාණය අනුව menu එක auto-මාරු වෙනවා — පහළ බොත්තම් පේළිය (දුරකථනය) → පැත්තේ පටිය (ටැබ්ලට්) → සම්පූර්ණ side menu + පැති දෙකේ layout (ලොකු තිර). මේ බොත්තම් ඔබලා බලන්න:

මේක අතින් හදන්නේ නෑ — Google ගේ නිල, stable "adaptive navigation" කොටසින්මයි. ඒ වගේම තිර අතර මාරු වෙන යටිතල පද්ධතියට Google දැන් අලුත් apps වලට නිර්දේශ කරන අලුත්ම stable ක්‍රමය (Navigation 3) පාවිච්චි කරනවා — internet එකෙන් verify කරලා.

"පාට්ස් ලැයිස්තුව" — ඔක්කොම අලුත්ම, ස්ථිර, verify කරපු

App එකක් හැදෙන්නේ Google/community එකෙන් එන "පාට්ස්" (libraries) ගොඩක් උඩ. නීති 2ක් තියාගත්තා: (1) අලුත්ම ඒත් "stable" (ස්ථිර යැයි ප්‍රකාශිත) versions විතරයි — beta/පරීක්ෂණ versions නෑ; (2) මගේ මතකයෙන් නෙවෙයි — හැම version එකක්ම internet එකේ නිල source දෙකකින් වෙන වෙනම verify කළා.

  3. "කඩන්න බලන" පරීක්ෂකයන් 3ක් — දිනපු සැලැස්ම වට්ටන්නම බලලා: නීති ලැයිස්තුවම trace කළා · test contract එක ගොනුවෙන් ගොනුවට simulate කළා · "Spanish Translator" add කිරීම step-by-step ඇවිද්දා.
